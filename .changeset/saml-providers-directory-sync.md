Add SAML 2.0 identity providers and SCIM 2.0 directory sync. `putIdentityProvider` (`PUT /v1/identity-provider`) takes an optional `protocol`. Without it the body is an OIDC provider, as before. With `protocol: "saml"` it takes `displayName`, `jit`, `metadata` as `{ url }` or `{ document }`, an optional `emailAttribute`, and an optional `unsolicitedSignIn` of `disabled` (the default) or `enabled` for IdP-initiated sign-in. `getIdentityProvider` returns either shape, discriminated by `protocol`. A SAML provider includes `serviceProvider` with the `entityId`, `acsUrl`, and `metadataUrl` to register with the identity provider, plus `singleSignOnUrl` and the signing certificates' `sha256Fingerprint` and `notAfter`. `deployments identity-provider set` takes `--protocol oidc|saml`, which defaults to `oidc`. For SAML it takes `--metadata-url` or `--metadata-file`, `--email-attribute`, and `--unsolicited-sign-in disabled|enabled`. The client secret flags apply only to OIDC.

Directory sync lets an organization's identity provider add, update, and remove members through SCIM 2.0 at `/scim/v2/Users`, authenticated with a directory bearer token. `getDirectory` (`GET /v1/directory`) returns the default role, the SCIM base URL, and the token list. `putDirectory` (`PUT /v1/directory`) turns sync on or sets `defaultRole` to `member` or `viewer`. `createDirectoryToken` (`POST /v1/directory/tokens`) returns the token's `secret`, which no other response contains. A directory holds at most two tokens, for rotation. `revokeDirectoryToken` (`DELETE /v1/directory/tokens/{id}`) revokes one. These operations take the `x-deployments-organization` header and need the owner or admin role, with `members:read` for reads and `members:write` for changes. The CLI adds `deployments directory show`, `deployments directory set --default-role`, `deployments directory token create`, which prints the secret only with `--reveal`, and `deployments directory token revoke`.
