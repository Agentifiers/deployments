The installation root in `infrastructure/environments/customer` turns on every feature that works without an input only you can supply. This page lists each feature with its variable, its default, and what it needs. [Install in your AWS account](/docs/operate/install) lists the variables every installation sets, and [Costs](/docs/operate/costs) lists what each feature costs to run.

### Web tools and NAT

The in-stack web tools need an egress path that refuses to forward to private and reserved IPv4 ranges. Only the NAT instance mode provides it, so while `web_tools_runtime_enabled` is `true`, `network_nat_mode` defaults to `instance`: one fck-nat EC2 instance, `network_nat_instance_type` `t4g.small` by default, carries all private-subnet egress, including Bedrock and ECR traffic. The root looks up the newest fck-nat AL2023 ARM64 AMI from its publisher at the first apply and keeps it; set `network_nat_instance_ami_id` to move to another AMI.

A NAT instance costs less than managed NAT gateways but is one instance in one availability zone, so an instance or zone failure stops egress until EC2 recovers it. To keep managed NAT gateways, one per zone, set `web_tools_runtime_enabled` to `false`. You can then point `agent_runtime_web_tools_enabled` at an external Firecrawl with `agent_runtime_firecrawl_base_url` and `agent_runtime_firecrawl_job_ticket_secret_arn`, or set it to `false` too.

### Memory and Brain search

Every organization gets working memory search and Brain search with no operator step. Creating an organization emits `organization.created`, and the memory runtime provisions that organization's index on the installation's OpenSearch domain with `memory_runtime_embedding_model` at 1,536 dimensions. A provisioning worker creates the index, verifies it with test writes and searches, and activates it. The activation then starts the Brain runtime, which creates the organization's Brain index with the same embedding model, activates Brain search, and queues every Brain document stored before then for indexing. Until the memory index is active, memory search, recall, and writes that update the index fail.

Each step retries on failure. Work that keeps failing lands in the `memory-search-placement-dlq`, `memory-operation-dlq`, or `brain-search-placement-dlq` dead-letter queue, and each raises an ops alert. `memory_runtime_reconciliation_scopes` is optional: it adds a five-minute drift repair between stored memories and the index for the environments you list, and search works without it.

Every deploy also runs the `activateSearchPlacements` stage, which activates any organization that still has no index, such as one created before your installation ran this release. Organizations that already have one are left unchanged. `bun run memory:search:control` and `bun run brain:search:control` stay available to move an organization's index to another target; `functions/memory-runtime/README.md` describes them.

### OCR for scanned PDF pages

Document extraction reads a PDF's text layer. A scanned page has none, so by default it contributes no text, and a PDF with no readable text at all resolves to `no_text`. Set `document_extraction_ocr_enabled` to `true` to read those pages with the Amazon Textract `DetectDocumentText` operation.

With OCR on, extraction sends a PDF page to Textract when its text layer holds fewer than 16 visible characters and the page paints an image. Blank pages and pages drawn only with vector shapes are not sent. Extraction sends at most 12 pages per file, the first ones in page order, each at most 10 MB, and at most 4 at a time. Scanned pages past the 12th stay without text, and the file's summary counts them, for example `PDF, 40 pages (12 read by OCR, 28 without text)`. PDFs inside a ZIP file and image files are never sent to Textract. The text of each page that OCR read starts with `--- Page N (OCR) ---`, so the model and Brain citations show which text came from OCR. Textract reads English, French, German, Italian, Portuguese, and Spanish. See [Amazon Textract best practices](https://docs.aws.amazon.com/textract/latest/dg/textract-best-practices.html).

Before you turn it on, check these:

- **Region.** Textract must run in the installation's Region. The plan reads the Region's Textract endpoint service and fails where there is none. See [Amazon Textract endpoints and quotas](https://docs.aws.amazon.com/general/latest/gr/textract.html).
- **Quota.** Each page is one `DetectDocumentText` call, and the account's quota is shared by every file read at the same time. The default is 10 transactions per second in us-east-2, 25 in us-east-1 and us-west-2, and 1 in most other Regions. When Textract keeps throttling, extraction reports the file as unavailable rather than storing a result. Completing an upload then answers `503 input_file_resolution_unavailable`, and Brain indexing retries later. Request an increase before you turn OCR on in a Region with a low default. See [Amazon Textract quotas](https://docs.aws.amazon.com/textract/latest/dg/limits.html).
- **Content use.** Page images leave the installation for Textract. AWS may use them to improve its AI services unless your AWS Organization applies an AI services opt-out policy that covers Textract. The installation does not set that policy. See [AI services opt-out policies](https://docs.aws.amazon.com/organizations/latest/userguide/orgs_manage_policies_ai-opt-out.html).
- **Cost.** Textract bills each page it reads, and a file that is read again, for example after a retry, is billed again. Inside the VPC, OCR also adds a Textract interface endpoint in each availability zone of the private subnets, billed per hour and per GB. See [Amazon Textract pricing](https://aws.amazon.com/textract/pricing/) and [AWS PrivateLink pricing](https://aws.amazon.com/privatelink/pricing/).

Inside the VPC, the extraction function reaches Textract only through that endpoint, and the endpoint's policy admits only the function's role. The endpoint has private DNS on, so inside the VPC the Region's public Textract name resolves to the endpoint. The endpoint admits only the extraction function, so other workloads in that VPC cannot call Textract unless the endpoint's security group and policy admit them. With `agent_runtime_enabled` set to `false`, the function runs outside a VPC and calls the Region's public Textract endpoint.

If reading a PDF leaves too little of its time limit for OCR, the file resolves to `limits_exceeded`. Turning OCR on does not change files the platform has already read. An input file that resolved to `no_text` stays `no_text`, and a Brain document version that failed for lack of text stays failed. Upload the file again to read it with OCR.

## Service models

The model gateway calls these models outside agent runs. Each must start with a provider prefix in `model_runtime_hosted_providers`, or the plan fails.

| Variable                                   | Default                                                           |
| ------------------------------------------ | ----------------------------------------------------------------- |
| `memory_runtime_embedding_model`           | `bedrock/global.cohere.embed-v4:0`. Must return 1,536 dimensions. |
| `memory_runtime_rerank_model`              | `bedrock/global.anthropic.claude-haiku-4-5-20251001-v1:0`         |
| `brain_runtime_answer_model`               | `bedrock/global.anthropic.claude-haiku-4-5-20251001-v1:0`         |
| `model_gateway_service_fallback_model_ids` | `["bedrock/global.anthropic.claude-haiku-4-5-20251001-v1:0"]`     |
| `web_tools_firecrawl_model_name`           | `bedrock/global.anthropic.claude-haiku-4-5-20251001-v1:0`         |
| `web_tools_firecrawl_embedding_model_name` | `bedrock/global.cohere.embed-v4:0`                                |

Both default models are also curated, so an environment without a model policy can run them. See [Models and model policies](/docs/capabilities/models).
