# @agentifiers/deployments-cli

## 0.1.0-alpha.2

### Minor Changes

- 11cfed8: Active recall returns more memory. `activeMemoryRecall` (`POST /v1/memory/active-recall`, CLI `deployments memory active-recall`) without `topK` now returns up to 32 memories instead of 10, within a 4,000-token budget instead of 1,200. When every memory the run can read fits in 32 memories and 7,000 tokens, recall returns all of them, oldest first, with ranks renumbered in that order and the original scores kept. A memory policy can lower that cap with `memoryRetrieval.fullContextTokenCap`, and 0 turns it off. The cap never rises above 7,000 tokens, because the agent prompt holds about that much memory text, and it never applies to memory search. A policy that already sets `contextTokenBudget` keeps ranked recall unless it also sets the cap. An explicit `topK` still limits the result count, and a whole set never exceeds 32 memories, even when `topK` is higher. Whole-set recall drops duplicates as ranked recall does, keeps the oldest copy, and counts the rest in the attempt's `duplicateCount`. Each recall attempt records its `selectionMode`, `whole-set` or `ranked`.
- 11cfed8: Add agent-built apps, internal web apps that deployed agents build with the `app.*` tools. Ten operations under `/v1/apps` list, read, update, archive, and erase apps (`listApps`, `getApp`, `updateApp`, `archiveApp`, `eraseApp`), manage member grants (`listAppGrants`, `putAppGrant`, `removeAppGrant`), and list and promote releases (`listAppReleases`, `promoteAppRelease`). They take a platform bearer token and the `x-deployments-environment` header. Reads need `apps:read`. Changes need `apps:write`, the owner or admin role, a human principal, and an `Idempotency-Key`, and an API key that tries one gets 403 `human_principal_required`. `eraseApp` answers 202 and deletes the app's database, roles, host routing, release files, and records. The app's slug is never reused. The CLI adds `deployments app list`, `show`, `update`, `archive`, and `erase`, `deployments app-grant list`, `set`, and `remove`, and `deployments app-release list` and `promote`. Tenant data exports now include one CSV per table of every active or archived app.
- 11cfed8: Serve agent-built apps on their active custom domains. The app gateway answers a custom hostname only while it is an `active` domain of the app, and answers 404 for any other hostname, including `unverified` and `verified` domains, before it reads the app or its database. A detached domain stops serving pages and API calls within 5 seconds. Members sign in on a custom domain only when a person attached it. On a domain an API key attached, sign-in moves to the app's slug URL. A session works only on the host where it was issued, and the sign-in callback checks the domain again before it sends the member back to it.
- 11cfed8: Activate custom domains of agent-built apps automatically. A new `apps-domains` Lambda converges CloudFront distribution tenants and their managed certificates to the domain records every 5 minutes and on demand. A `verified` domain gets a tenant with a CloudFront-managed certificate; once the certificate is issued it is attached, and once CloudFront serves the hostname the domain moves to `active`. `refreshAppDomain` now also queues that convergence for the domain and answers the domain as it stands, without waiting; the queued run re-requests a failed or timed-out certificate. Poll the domain to follow the setup. `detachAppDomain` queues the convergence, so the tenant is disabled within seconds and deleted, with its certificate, on a later run.

  When CloudFront rejects the tenant for a domain, the platform tries again after 10 minutes, then after twice as long each time, up to once a day, whether a sweep or a refresh asks. Every TLS certificate request also counts against a daily limit for the organization (5 by default) and for the installation (12 by default), counted in UTC days, which keeps an installation under ACM's 5,000 certificates a year. Detaching and attaching a hostname again does not reset them.

  Domain `problem` gains four codes: `previous_tenant_draining`, recorded while a hostname that was detached and attached again waits for its earlier tenant to be deleted; `edge_rejected`, recorded when CloudFront rejects the hostname itself, usually because its `CNAME` does not point at the routing endpoint yet; and `organization_certificate_limit` and `platform_certificate_limit`, recorded when a daily certificate request limit is spent. The platform makes the request on its own after 00:00 UTC.

  Installations that set `APPS_DOMAIN` for the API now also set `APPS_DOMAIN_RECONCILER_FUNCTION_NAME`, and the API refuses to start without it. The platform module wires it, and the deploy pipeline publishes the new `app-domains` Lambda artifact. The `apps-domains` Lambda reserves a concurrency of 1, does not retry a failed run, and drops a queued event after 10 minutes. When it drops the run a refresh queued, the failed or timed-out certificate is not requested again until the next refresh. The `apps-domains-deferred-steps` alarm notifies the platform alarm topic when every sweep for 15 minutes runs out of time.

- 11cfed8: Add custom domains to agent-built apps. Four operations manage them. `listAppDomains` (`GET /v1/apps/{appId}/domains`) needs `apps:read`. `attachAppDomain` (`POST /v1/apps/{appId}/domains`), `refreshAppDomain` (`POST /v1/apps/{appId}/domains/{domainId}/refresh`), and `detachAppDomain` (`DELETE /v1/apps/{appId}/domains/{domainId}`) need `apps:publish` and admit the same members and API keys as `setAppPublication`. The CLI calls them with `deployments app-domain list|attach|refresh|detach`.

  Attach takes `{ hostname }` and answers 200 with the domain and the DNS records to publish: a `TXT` record `_deployments-app.<hostname>` = `deployments-app=<token>` and a `CNAME` to the installation's routing endpoint, with a note on ALIAS, ANAME, or CNAME flattening for a zone apex. Attaching a hostname the app already holds returns the existing domain. The API trims and lowercases the hostname. A hostname that is not a multi-label ASCII name of at most 236 characters answers 422 `invalid_hostname`, because a longer one would push the `TXT` name past the 253 characters DNS allows. The installation's own hostnames and every name under them answer 422 `hostname_reserved`. Refresh checks the `TXT` record and moves the domain from `unverified` to `verified`. It needs no `Idempotency-Key`. It answers 422 `txt_not_found`, 409 `domain_claimed` when another app, in any organization, verified the hostname first, and 503 `dns_lookup_failed` when the lookup fails. A refresh before the `TXT` record exists can leave resolvers answering `txt_not_found` for up to the zone's negative-caching TTL. An app holds at most 10 domains, and an organization at most 50 verified domains. Erasing an app detaches its domains first.

  Installations that set `APPS_DOMAIN` for the API now also set `APPS_CUSTOM_DOMAIN_TARGET` and `APPS_RESERVED_HOSTNAMES`, and the API refuses to start without either. The platform module wires the first from the app runtime's routing endpoint and the second from the API, identity, console, and stream gateway hostnames.

- 11cfed8: Find an agent-built app by its slug. `listApps` (`GET /v1/apps`) takes `slug` and then returns that app, or an empty list when no app in the environment has the slug, from one read instead of a page per 100 apps. `deployments app list --slug <slug>` calls it.
- 11cfed8: Add publication settings to agent-built apps. Every app response now carries `publication: { audience, serving }`, where `audience` is `members` or `public` and `serving` is `single-page` or `static-site`. An app that never set them reports `members` and `single-page`. `setAppPublication` (`PATCH /v1/apps/{appId}/publication`) changes either field or both, with an `Idempotency-Key`, and `deployments app set-publication <id> --audience public --serving static-site` calls it. Setting `audience` to `public` first brings the app's database up to the current layout, and so does the first `app.migrate` on an app created before this release. For 10 minutes after that step starts, an erase of the app is refused with 409 `app_state_conflict`, so the step cannot recreate the database of an erased app.

  The route needs the new `apps:publish` scope. Members also need the owner or admin role. A service-account API key may call it only when the key and its service account both name `apps:publish`, because `apps:*` and `platform:*` do not grant it to API keys. A key can create a service account or key that names `apps:publish` only when the key names it too. Every other app change still needs a human principal. CLI and console sessions request `apps:publish` from now on, so a member who signed in before this release must sign in again to publish.

- 11cfed8: Schedule, heartbeat, and run responses gain optional fields that trace an automation to its creator and its runs. `createdBy` names the actor that created a schedule or heartbeat: the calling principal or service account, or the agent deployment for the built-in scheduling tools. `createdFrom` names the tool call (`runId`, `threadId`, `toolCallId`, and `toolName`) when `agent.schedule.create` or `agent.schedule.remind` created a schedule. Runs started by a schedule or heartbeat fire carry `automation` with the automation's `kind`, `id`, and `fireId`. Replays do not. Automations created before the API recorded these fields have no `createdBy` or `createdFrom`.
- 11cfed8: Add Amazon Bedrock as a model provider. Model ids take the form `bedrock/<foundation model or inference profile id>` (for example `bedrock/us.anthropic.claude-haiku-4-5-20251001-v1:0`). The model catalog `provider` filter, `model list --provider` options, and the SDK `MockModelProvider` type now accept `bedrock` alongside `openai` and `openrouter`.
- 11cfed8: Brain content uploads now reach the documented 8 MiB. Before, the content `PUT` refused files above about 4.7 MB with `413`, because the body is base64-encoded into Lambda's 6 MB request payload. An issued upload ticket now includes `directUpload`, a presigned storage `PUT` and the `completePath` to call after it. The new SDK helper `uploadBrainContent` stores the bytes through `directUpload` and completes the ticket, or falls back to the content `PUT` for a ticket without `directUpload`. Resending with the same idempotency key converges. `deployments brain-upload content` uses it, and the new `deployments brain-upload complete` completes a ticket whose content was stored through its direct upload. The content `PUT` still works for existing clients.
- 11cfed8: `deployments chat` attaches files with `--file <path>`, which replaces `--image`. `--image` is removed with no alias. `--file` takes a PDF, Word (.docx), Excel (.xlsx), CSV, text, Markdown, JSON, HTML, or ZIP file, or a JPEG, PNG, or WebP image, and repeats for up to eight files. Before it calls the API, the CLI refuses a file over 10 MiB, images and audio that total more than 20 MiB, and a legacy Office file (`.doc`, `.xls`, `.ppt`) or a `.pptx` file, with the same reason text the API uses. The CLI declares each file's content type from its extension. A file whose extension it doesn't know uploads as `application/octet-stream`, and the platform types it from its bytes. Without `--thread`, the CLI creates the thread first. Each file uploads to the thread with `type: "input"` and a 30-day retention. When an upload completes with `input.kind` `unusable`, the command exits with code 7 and the platform's message, and it does not submit the run. For example: `scan.pdf can't be attached: the file has no readable text. If it is a scan, OCR found no text or isn't turned on.` A rerun uploads the files again, so a retry with the same `--idempotency-key` after a submission that went through fails with an idempotency conflict.

It refuses a storage URL that is not HTTPS unless the host is loopback. `PlatformSdk` gains `uploadPresigned`, which the mock transport implements without sending bytes. Mock run submissions now echo `inputArtifacts` on the message.

A visitor who is not signed in and calls an `api` function or an unknown name gets 401 `unauthenticated`, and a person whose session the app refuses gets that refusal, such as 403 `not_a_member`. The gateway limits them per address and app (a burst of 10, then 10 per minute), per app (120, then 300 per minute), by body size (16 KiB), by concurrency (2 per app, 16 per gateway task), and by time (2 seconds, after which the call is rolled back and answers 504 `deadline_exceeded`). A call that sent its commit and got no answer from the database answers 504 `outcome_unknown`, because its changes may have been saved, so retrying it may write twice. A migration that gives a function its own `statement_timeout`, `transaction_timeout`, `idle_in_transaction_session_timeout` or `client_connection_check_interval` is refused. The gateway limits visitor pages to a burst of 60, then 300 per minute, per address, and does not count redirects: the 307s that send asset paths to the release's files and the 308s that add or remove a trailing slash. A session now works only on the host where the person signed in. The generated TypeScript client sends the browser to sign-in only on 401 `unauthenticated`, and `PlatformApiError` gains `retryAfter`, the seconds from the `Retry-After` header.

- 11cfed8: A device token refresh that fails for a transient reason no longer logs the CLI out. Before, a network error, timeout, or `5xx` from `/v1/device-authorizations/token`, or a failed `/v1/whoami` check after the exchange, removed the stored refresh token, so the next command asked for `deployments auth login`. Now the profile keeps its refresh token and the next command refreshes again. When the exchange succeeded but the identity check failed, the profile keeps the rotated refresh token and not the unchecked bearer. Only `invalid_grant`, `invalid_client`, or `unauthorized_client` marks the profile for a new login. Concurrent commands still share one token exchange through the per-profile refresh lock.

  Within one command, a transient exchange failure is resent up to twice. The 30-second refresh deadline now bounds every resend and the `/v1/whoami` check together; before, on Bun, the deadline stopped after the first resend delay.

  A `200` from the token endpoint whose body is cut off or unreadable counts as a lost response and is resent, because identity-api already rotated the token. Before, it failed the command with `null is not an object`.
